# Building SIMD Assembly from C Code

This document explains how to compile C code into Go assembly using the `goat` tool.

## Overview

Vex uses SIMD-optimized assembly code generated from C source files. The generation process uses the [goat](https://github.com/mmcloughlin/goat) tool, which converts C code with SIMD intrinsics into Go assembly.

## Directory Structure

```
internal/vector/
├── c/                          # C source files (hand-written)
│   ├── dot_avx256_amd64.c     # AVX2 implementation
│   └── dot_avx512_amd64.c     # AVX512 implementation
├── asm/                        # Generated assembly (auto-generated)
│   ├── dot_amd64.go           # Main wrapper with //go:generate directives
│   ├── dot_avx256_amd64.go    # Generated by goat (DO NOT EDIT)
│   ├── dot_avx256_amd64.s     # Generated by goat (DO NOT EDIT)
│   ├── dot_avx512_amd64.go    # Generated by goat (DO NOT EDIT)
│   └── dot_avx512_amd64.s     # Generated by goat (DO NOT EDIT)
├── dot_product.go             # Public API
├── dot_product_amd64.go       # CPU feature detection
└── dot_product_test.go        # Tests
```

## Prerequisites

### Option 1: Using Docker (Recommended)

We provide a Docker image with goat pre-installed:

```bash
# Build the Docker image (if not already built)
docker build -f Dockerfile.goat -t goat-builder:latest .
```

### Option 2: Install goat locally

**Note**: goat requires a working LLVM/Clang installation.

```bash
go install github.com/mmcloughlin/goat@latest
```

## Generating Assembly Code

### Method 1: Using Docker

This is the recommended approach as it ensures a consistent build environment:

```bash
# Start the Docker container
docker run -it --rm \
  -v ~/wp/vex:/app \
  -w /app/internal/vector/asm \
  goat-builder:latest bash

# Inside the container, generate AVX2 assembly
goat ../c/dot_avx256_amd64.c \
  -O3 -mavx2 -mfma \
  -e="-mfloat-abi=hard" \
  -e="-Rpass-analysis=loop-vectorize" \
  -e="-Rpass=loop-vectorize" \
  -e="-Rpass-missed=loop-vectorize"

# Generate AVX512 assembly
goat ../c/dot_avx512_amd64.c \
  -O3 -mavx2 -mfma -mavx512f -mavx512dq \
  -e="-mfloat-abi=hard" \
  -e="-Rpass-analysis=loop-vectorize" \
  -e="-Rpass=loop-vectorize" \
  -e="-Rpass-missed=loop-vectorize"

# Exit the container
exit
```

**Generated files:**
- `dot_avx256_amd64.go` - Go declarations for AVX2 functions
- `dot_avx256_amd64.s` - AVX2 assembly implementation
- `dot_avx512_amd64.go` - Go declarations for AVX512 functions
- `dot_avx512_amd64.s` - AVX512 assembly implementation

### Method 2: Using go generate

If goat is installed locally, you can use Go's generate command:

```bash
cd internal/vector/asm
go generate
```

This executes the `//go:generate` directives in `dot_amd64.go`:

```go
//go:generate goat ../c/dot_avx256_amd64.c -O3 -mavx2 -mfma ...
//go:generate goat ../c/dot_avx512_amd64.c -O3 -mavx2 -mfma -mavx512f -mavx512dq ...
```

## Compiler Flags Explained

### Optimization Level
- `-O3`: Maximum optimization level

### SIMD Instruction Sets
- `-mavx2`: Enable AVX2 (256-bit) instructions
- `-mfma`: Enable Fused Multiply-Add instructions
- `-mavx512f`: Enable AVX-512 Foundation instructions
- `-mavx512dq`: Enable AVX-512 Doubleword and Quadword instructions

### Extra Flags (`-e`)
- `-mfloat-abi=hard`: Use hardware floating-point ABI
- `-Rpass-analysis=loop-vectorize`: Report loop vectorization analysis
- `-Rpass=loop-vectorize`: Report successful vectorizations
- `-Rpass-missed=loop-vectorize`: Report missed vectorization opportunities

## Verifying Generated Assembly

### Check the generated files

```bash
cd internal/vector/asm
ls -lh *.s *.go
```

Expected output:
```
-rw-r--r-- 1 user user  156 Jan 28 17:31 dot_avx256_amd64.go
-rw-r--r-- 1 user user 9.5K Jan 28 17:31 dot_avx256_amd64.s
-rw-r--r-- 1 user user  156 Jan 27 16:27 dot_avx512_amd64.go
-rw-r--r-- 1 user user  15K Jan 27 16:27 dot_avx512_amd64.s
```

### Run tests

```bash
cd internal/vector
go test -v
```

All tests should pass. If you see errors like "undefined: dot_256", the assembly generation failed.

## Modifying C Source Code

### Editing C files

C source files are in `internal/vector/c/`:

```bash
# Edit the source
vim internal/vector/c/dot_avx256_amd64.c

# Regenerate assembly
docker run -it --rm \
  -v ~/wp/vex:/app \
  -w /app/internal/vector/asm \
  goat-builder:latest \
  goat ../c/dot_avx256_amd64.c -O3 -mavx2 -mfma

# Test the changes
cd internal/vector
go test -v
```

### C Code Guidelines

1. **Use Intel intrinsics**: Include `<immintrin.h>` for SIMD intrinsics
2. **Optimize loops**: Unroll loops for better performance
3. **Match signature**: Function signature must match Go expectations
4. **Test thoroughly**: Verify correctness across all dimensions

Example C function signature:
```c
void dot_256(float *a, float *b, float *res, long *len)
```

## Troubleshooting

### goat fails to parse C code

**Error**: "expected declaration: IDENTIFIER"

**Solution**: This is often due to incompatible system headers. Use the Docker method which has known-good headers.

### Generated assembly causes segfault

**Cause**: Usually pointer arithmetic or register handling errors

**Debug steps**:
1. Check the C code for buffer overruns
2. Verify loop conditions
3. Test with small vectors first
4. Compare with working Weaviate implementation

### Tests pass but performance is poor

**Check**:
1. Verify SIMD instructions are actually used: `go test -bench=. -benchmem`
2. Check CPU supports required instructions: `grep avx2 /proc/cpuinfo`
3. Ensure optimization flags are correct in goat command
4. Profile with `go test -bench=. -cpuprofile=cpu.out`

## CI/CD Integration

### Checking pre-generated assembly

Generated assembly files should be committed to the repository:

```bash
git add internal/vector/asm/*.s internal/vector/asm/*.go
git commit -m "chore: update generated SIMD assembly"
```

### Testing without SIMD (for CI)

CI environments may not support SIMD. Tests support a `noasm` build tag:

```bash
# Test without assembly (pure Go fallback)
go test -tags=noasm ./...
```

### GitHub Actions example

```yaml
- name: Test with SIMD
  run: go test ./...

- name: Test without SIMD (noasm fallback)
  run: go test -tags=noasm ./...
```

## Performance Validation

After generating new assembly, always run benchmarks:

```bash
cd internal/vector

# Run before changes
go test -bench=BenchmarkDotProductComparison -benchtime=3s | tee before.txt

# Regenerate assembly with your changes
# ...

# Run after changes
go test -bench=BenchmarkDotProductComparison -benchtime=3s | tee after.txt

# Compare (if benchstat installed)
benchstat before.txt after.txt
```
